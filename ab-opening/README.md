# SNDK opening A/B template — inactive

These files prepare one experiment on the shared V3 basis engine. The authorization example has `approved_live: false`; the live launcher rejects it. This directory contains no activation script. Apply the reviewed code manually before preparing a separate live authorization. Do not overwrite the ordinary batch authorization, configuration, or journal.

The experiment admits 20 independent entry attempts, alternating A then B, ten per group, with a maximum of 200 USD per leg. A dispatches equal common units as two parallel taker IOC orders. B waits for Entropy's canonical terminal cumulative fill, then sends the corresponding unmatched H quantity. Only this experiment uses a null cumulative loss budget. All other entry gates, quantity rounding, IOC rooms and hard caps, request reserves, residual recovery, fees/funding accounting, and the 2.5 bp gross exit gate, measured against the immutable actual matched opening notional remain shared. A partially overhedged H is reduced with an exact reduce-only order.

An attempt is counted when its slot, opportunity, cycle, paired plan and initial intents commit together, before sending. Zero fill, rejection, partial recovery and UNKNOWN resolution all consume that slot; IOC retry waves retain it. The journal never refunds admitted slots. A sustained executable signal cannot claim another slot. Rearming requires a fresh valid market/reference observation with no executable opening plan. Lack of resources or stale/missing data does not rearm. The next slot additionally requires all previous orders terminal, fresh authoritative flat evidence covering their watermarks, and zero canonical inventory. After slot 20 the engine continues recovery and exits without admitting more entries.

Use a new experiment batch ID. The example identity assumes deployment `default`, HL SNDK and Lighter SNDK; verify it against the intended launch. Experiment identity, batch, configuration, authorization and local source fingerprint bind on first initialization and must remain identical on restart. Reuse the existing account lock and `logs/v3/journal.sqlite3`; recovery resolves the same durable IDs. Use separate output arguments, for example `--status-json logs/v3/ab/status.json --observer-jsonl logs/v3/ab/observer.jsonl`, so ordinary and experiment telemetry remain distinguishable. The V3 configuration argument must explicitly point to `ab-opening/config.v3.opening-ab.example.json`, rather than an ordinary edge configuration.

The configuration copies edge-next settings, adds the experiment ID, and removes the three old batch-scoped Lighter zero-fee policy fields. The old policy does not authorize the new experiment batch. Before any manual live activation, verify the new batch's applicable fee evidence; otherwise accounting uses actual adapter fee evidence. Both groups share that treatment. No live authorization or fee-policy evidence is generated here.

Read-only verification should inspect the effective manifest's `opening_experiment_contract`, including source/config/authorization hashes, and the journal's `opening_experiments` and `opening_attempts` rows. Each row exposes its slot/group/opportunity, paired plan, IDs, outcome and terminal-flat completion. The status contains current allocation and group counts. Execution completion is independent of final fee/funding accounting; missing accounting evidence stays pending and is never converted to zero.

A's execution-loss benchmark uses each leg's own submission quote at its actual filled quantity. B retains the sequential Entropy-fill/H-anchor definition, so these loss sums must not be mixed as an identical metric. A's sequential B-to-C/C-to-D and first-fill decay decomposition are null because the legs can finish in either order; canonical net PnL remains comparable. Existing clean serial-summary eligibility may exclude A because those decomposition fields are unavailable. Local first observation uses the earliest positive opening receipt; the earliest exchange fill is recorded only when every positive opening leg has an actual exchange timestamp.

Verification uses only isolated SQLite files and fake transports through the production senders. It covers atomic rollback, alternation/counting, restart with the same IDs, UNKNOWN, partial recovery, cold nonce final gates, benchmark completeness and ordinary budget behavior.
