# 完整套利循环代码审查与修改方案

审查日期：2026-09-08。对象为当前工作区（包括未提交改动），不是只审查 Git HEAD。此次仅审查与提出方案，不改变交易配置、不启动交易。

## 结论

当前实现已经具备四阶段执行成本、FIFO 成交成本、完整周期记录、行动独立冷却及执行 campaign。问题不是简单“约束太多”，而是：部分约束放错层级，会阻断退出；经济预测仍依赖价差回归情景；自适应估计混入历史长尾且不能及时适应市场变化；回放与实盘决策不一致。

建议先修完整循环可结束性和成本口径，再优化条件期望与周转率，最后提高订单预算。不要先全面降低入场门槛或放宽滑点。

## 证据与范围

- 最新 `logs/status.json` 时间为 2026-09-06 15:13:55 UTC（北京时间 23:13:55），不是当前实时状态。后续 `logs/launchd.stderr.log` 持续出现项目目录及 `scripts/run_live.sh` 的 Operation not permitted；尚未验证当前进程状态，不能从旧快照的 running 推断服务正在运行。
- 快照 session 漏斗：466 个 signal episode → 10 个 economic opportunity/campaign → 3 次 OPEN fill → 3 次 hedge complete → 2 次完整正常执行闭环。不是独立机会样本的成功概率估计。
- 同一快照近期 cycle 汇总含 3 个 completed，其中 2 个 clean、1 个 recovery；不同计数包含不同退出类型，不能混为一个口径。
- SQLite 只读审查：68 个 cycle records，包括 54 个 aborted 和 14 个 completed。14 个历史 completed 的已记录净收益合计约 -$0.220180。最近两个 normal_profit 周期为 +$0.003096、+$0.004079；这些记录跨历史配置，既不能用历史总亏损断言当前版本负期望，也不能用最近两次盈利证明当前版本正期望。
- 快照 flat 时两腿仍有约 ±0.0001 base 残量；净 delta 为零不等于两个账户实际清零。需显式区分精确 FLAT、交易所允许的不可交易 dust、未完成 cycle。
- 最新 sell_entropy 经济检查示例：回归情景扣四腿费用后约 +$0.002156，减预测执行成本 $0.004953、不确定性 $0.003453、安全余量 $0.000743 后为 -$0.006992（该方向资金费 reserve 为 0）。因此资金时间预测并不是全部拒单的原因；仍需分别校准真实可赚空间、成本估计与风险余量，不能只降一个阈值。

## 主要发现

### 1. P1：缺失成交账务可以无限挡住 REDUCE，甚至挡住保证金风险退出

位置：`entropy_arb/engine.py:6399`、`:6494`、`:8084`、`:8102`。

只要 active_execution 存在，evaluate 先进入 recovery 并返回。若交易所仓位显示已经配平，但成交价格/历史尚未补齐，则持续等待 fill facts；recovery timeout 不为这种持仓释放路径。其后的保证金风险检查也无法执行。

修改：拆开订单是否仍可能成交、仓位风险是否已覆盖、账务是否完整三个事实。未知订单仍禁止盲目补 hedge 或新 OPEN；对已确认订单终态和真实持仓的 reduce-only 风险退出，不应等待会计价格补齐。补账在后台继续，原始 execution/cycle ID 保留关联。仅有净仓位配平不能充当原订单终态证明。

验收：模拟 hedge 仓位已覆盖但 fill history 缺失；不重复 hedge，不新 OPEN；在订单终态可证实且风险触发时可以安全 REDUCE；成交历史迟到后只入账一次。

### 2. P1：开仓最小金额复用于退出，部分成交可制造永久尾仓

位置：`engine.py:6548`、`:6599`、`:7614`、`:7625`、`:9223`；当前 sizing 最大 $15、最小 $10。

例如 $15 配对仓位先部分减掉 $10，剩余约 $5，正常 REDUCE、hedge 合法性和 emergency 路径都可能被策略的 $10 门槛挡住，即使交易所允许这种减仓订单。

修改：OPEN 的经济最小金额与 venue 的 min quantity/min notional/step 分开。REDUCE 和 recovery 根据真实交易所规则及 reduce-only 例外执行；预先避免产生不合法尾仓。若交易所确实无法清除尾量，应登记 dust 及其估值，不能虚报严格 FLAT。

验收：整单、部分 REDUCE、小额剩余、不同 venue step、不可交易 dust；不得为消尾仓无界增仓。

### 3. P1：退出经济均价与可执行限价混用，深盘口时有预算也可能减不了仓

位置：`engine.py:5293`、`:5314`、`:5797`、`:5985`。

expected reserve 明确不含盘口深度，但 expected hedge bound 仍从 top-of-book 推导。close builder 随后要求该 bound 覆盖完整数量的 marginal price。若深度需 3 bps、expected reserve 只有 1.5 bps，该判断失败，不会进一步使用足够的完整周期预算寻找可执行边界。

修改：经济现金流使用 depth VWAP 加增量执行成本；IOC 可执行边界依据 marginal price、可负担空间和独立物理上限构造。对冲预算只扣一次，不能为提高成交率重复扣深度，也不能为了通过检查遗漏深度。

验收：多档买卖盘口、marginal 与 VWAP 明显不同；足够预算时可下合法 REDUCE，不足预算时准确拒绝；第一腿成交后 hedge 继续按风险/物理限制完成。后者当前已存在，应保留。

### 4. P1：hard timeout 不是最大持有时间，周期仍可能无限等待回本

位置：`engine.py:5688`；`entropy_arb/control_plane.py:145`。

当前 3600 秒后仍需净收益达到 -$0.02，否则停在 forced_release_pending。动态退出地板硬编码 0/-0.5/-1/-2 bps，300 秒后不再变；另叠加 FAST 的美元地板。对于 $15 名义金额，-2 bps 只有 -$0.003，不能释放明显偏移的持仓。

修改：统一退出政策，明确“经济择时退出”与“最大持有/风险释放”。经济退出比较继续持有的增量收益与立刻退出；风险释放达到触发条件后不再要求先恢复到单次利润地板，而是在真实可用盘口、reduce-only、物理价格边界内分步退出。损失阈值是触发器，不能承诺成交损失绝不超限；交易所不可用时应明确为未完成恢复状态。

`pnl_loss_stop_enabled` 等字段在该分支主要产生遥测，并未实际授权对应退出。当前配置为关闭，因此这不是本次运行“已启用止损失效”的证据，但需要实现其语义或明确废弃。

验收：正常回归、小亏快速释放、持续漂移超时、数据中断、风险时部分成交；不能仅检查状态名字变成 timeout，必须验证两腿减仓及最终仓位。

### 5. P1：当前 expected_cycle_pnl 是回归情景收益，不是真正的完整周期 EV

位置：`engine.py:5513` 至 `:5613`。

模型平移当前退出盘口到目标基差，扣除四腿手续费、资金费和执行成本，却没有显式考虑限定时间内不回归、风险退出和恢复失败的概率及成本。旧中枢看起来还有回归空间，不表示市场会及时回归。

修改：先将该指标明确标为 projected PnL。用统一退出政策下的有限期限结果分布估计 cycle EV：正常/时间/风险/恢复退出的概率、净收益与耗时。样本不足时使用保守先验和明确的数据置信度，不伪装成已经证明的正期望。

实际周期净收益以真实成交现金流减实际费用加净资金费归因；滑点已经进入成交价，不能再次扣除。预测预算才独立计入未发生的滑点和延迟成本。

验收：时间顺序样本外回放；按方向、市场状态和配置版本对比预测与实际净收益。纳入所有失败周期及未结束库存的保守可执行退出价值，不能只选成功闭环。

### 6. P2：持仓预测固定下限 + 混合历史，放大快速循环的资金成本

位置：`engine.py:1495`；`entropy_arb/trade_ledger.py:2491`。

即使实际 P90 为 20 秒，函数仍返回至少 600 秒；无样本先验为 2 小时。历史 duration 查询未区分日期、配置及退出类型，本地 14 个 completed 的 P90 约 5518 秒，和快照近期三个 cycle 的 P90 约 19.56 秒不是同一统计口径。

修改：持有时间预测与当前退出政策保持一致，按近期、方向及版本做适度收缩；去掉无依据的 600 秒下限。历史恢复长尾应进入尾部风险，不应简单删掉亏损样本；未结束周期作为删失样本/存续风险保留。资金费遵循交易所实际结算规则。

验收：20 秒近期循环不会被无条件当成 600 秒；存在未完成长持仓时预测不能仅凭完成样本变乐观。

### 7. P2：十个成交样本后，实时成本变化完全失去权重

位置：`entropy_arb/execution_cost.py:318` 至 `:348`。

empirical weight 达到 1 后 live prior 权重为零，样本按数量滚动、不按时间衰减。直接运行验证：10 条 0.1 bps 样本后，live adverse move 从 0.1 提到 8 bps，expected cost 仍约 0.1 bps。反过来，旧高成本也可能长期抬高门槛。

修改：保持实时市场变化可影响成本；使用时间衰减及有限条件分组，或历史基准加经过校准的实时修正。均值/概率期望与尾部风险分开，不把四腿高分位数相加直接称为无偏期望，也不把物理最坏限价作为每次必付成本。

验收：成本骤升能及时保守响应；恢复平静后能逐步回落；无样本、少量样本、方向/规模变化都有可解释结果。

### 8. P2：发送预算与完整循环资源需求不一致

位置：`engine.py:1044` 至 `:1084`；当前两 venue 均设置 6 次/分钟。

共用全部 sends 窗口，实际 OPEN 门槛为 4、REDUCE 为 5。无重试理想路径各 venue 每 cycle 发两次，约两个 cycle 后第三次 OPEN 就需要等待窗口释放；零成交重试会更快吃掉预算。设置 OPEN=8、REDUCE=10 不会突破这个共享门槛。

修改：明确实际交易所/API/账户限额与策略预算不同；为完整循环保留首腿、hedge、退出及有限恢复容量。调度优先级为风险恢复和未覆盖 hedge，其次 REDUCE，最后 OPEN。根据有利可执行机会和真实限额调整吞吐，不能仅按旧注释提高频率。

验收：零成交风暴下仍有退出/hedge 容量；可解释区分发单预算、campaign 次数、成交数量；提高预算必须带来完整 cycle/h 改善而非仅 requests/h 增加。

### 9. P2：部分“可调参数”不再控制实际逻辑

位置：`engine.py:4040`、`:5004`、`signal.py:302`。

lag/regime/volatility 已主要改为软经济项；episode campaign cap 和 reopen improvement 已不再是原先硬门禁。旧字段及展示仍容易误导。另一方面 adaptive band 的 floor 为 max(base, min)，只会比基础带更严，平静市场不能低于基础带。

修改：展示实际生效政策，明确 ignored/兼容字段，逐步删掉无效旋钮。候选发现可较宽松，统一 cycle EV 决定是否占用资本；避免多个统计阈值反复计入同一不确定性。先验证机会价值，再决定中枢窗口与带宽调整。

### 10. P1：现有 replay 不能作为实盘高频正期望验收器

位置：`tools/replay.py:553`、`:618`。

两腿按同秒报价全量成交，没有真实 hedge 延迟、拒单、部分成交和恢复调度；期末中价 MTM 混入 net_pnl，未扣剩余仓位完整退出成本。文件自身说明是 top-of-book study，应保留这一定位。

修改：让实盘和回放复用同一决策函数及退出政策，模拟成交/确认延迟、IOC 零成交/部分成交、重试、费用和订单预算。现有 1 秒 top-of-book 只能给粗略情景区间；亚秒执行需额外记录事件时间、深度及回执。

验收：相同输入产生相同候选/拒绝原因；延迟与成本压力增加时结果合理恶化；期末未平库存不伪装成已实现收益。

### 11. P2：闭环频率与已结算净收益的统计口径仍需修正

位置：`trade_ledger.py:2771`、`:2785`、`:1681`、`:2899`。

cycle_summary 按首成交时间选择周期，以 flat_ts 非空判完成，没有限定 flat_ts <= 查询截止时间；会漏掉窗口外开仓、窗口内完成的周期，历史截面又可能提前算入以后完成的周期。频率分母从首成交开始，遗漏启动后等待首单的时间。

手续费回补更新 fills 与剩余 lot 费用，但缺少同步重算已经保存的 completed cycle PnL 的路径。当前 14 个 completed 重算差异仅约 0–0.000001 美元，未发现重大现实错记；这是未来费用修正可能破坏 EV 统计的一处依赖缺口。

修改：分开首成交 cohort 完成率与按 flat_ts 统计的窗口吞吐量；频率分母使用明确记录的策略在线秒数。对 cycle 标注暂估/已对账，费用回补后重算关联周期。验收覆盖跨窗口闭环、首单前长等待、历史时点查询和闭环后非零手续费修正。

## 实施顺序

| 阶段 | 修改范围 | 完成条件 |
| --- | --- | --- |
| A：让循环可结束 | 恢复优先级、独立账务状态、尾仓、深盘口限价、真正风险释放 | 故障注入中无重复下单；能安全退出的库存不会因统计/会计门禁卡死 |
| B：让成本预测可信 | 四腿预算职责、持有时间、自适应执行成本、政策生效展示 | 不重扣成本；市场变化能更新预测；预测与实际可归因 |
| C：让策略优化可检验 | 同源 replay、有限期限 cycle EV、失败及未平仓归因 | 时间顺序样本外结果覆盖全部资金结果，输出不确定区间 |
| D：提高真实周转 | 候选带宽、机会排序、预算和重试联合调整 | 在同等风险/资金限制下增加净收益与完整 cycle/h，尾部风险不失控 |

不建议先大拆 10,000 行 engine 或添加更多状态/配置。先在现有执行与成本模块内完成可验证修复，再仅提取实盘/回放必须共享的纯决策逻辑。

## 目标与验收口径

优化目标为单位时间的全部净收益，同时约束资金占用、最大回撤、未对冲风险与尾部持仓时间；完整 cycle/h 是关键运营指标，不能脱离净收益单独最大化。

- 完整 cycle：至少有实际 OPEN、配对 hedge、退出成交，两腿按明确的 FLAT/dust 政策结束。正常与恢复闭环分别展示，均进入总盈亏。
- 主表：所有周期净收益、complete cycles/h、持有时间 P50/P90/P99、未对冲时间、资金占用、每闭环发单数、预测误差、强制退出率、未完成库存及其保守退出价值。
- 漏斗：候选 → 经济机会 → 首腿发送/成交 → hedge 完成 → 退出机会/成交 → FLAT。拒绝原因同时给持续时间与经济缺口；扫描次数不等于独立机会次数。
- 策略验证按时间顺序切分训练/验证及不同市场状态；对相关周期使用时间块置信区间，禁止仅看胜率或少数获利交易。样本量目标由净收益方差与置信区间决定。
- 验证通过后才考虑有限名义和明确亏损预算的实盘对照。当前审查不包含重启、调仓或自动增加实盘探索预算。
